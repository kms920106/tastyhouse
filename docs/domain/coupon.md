# 쿠폰(coupon) 도메인

## 이 도메인은 무엇인가

주문 금액을 할인해 주는 쿠폰을 다루는 영역이다. 관리자가 할인 조건을 정해 쿠폰을 만들고, 그 쿠폰을 회원에게 발급하고, 회원이 주문 결제 때 쓰는 흐름 전체를 담당한다.

이 도메인을 이해하는 데 가장 중요한 것은 **쿠폰 원장과 회원이 보유한 쿠폰이 서로 다른 것**이라는 구분이다. 이 둘을 혼동하면 "쿠폰을 지웠는데 회원이 아직 갖고 있다"거나 "회원이 썼는데 쿠폰 정보는 그대로다" 같은 상황을 오해하게 된다.

## 핵심 개념

**쿠폰 원장**은 관리자가 만드는 할인 조건 그 자체다. "신규 가입 5,000원 할인"처럼 쿠폰의 이름·설명과 할인 방식, 최소 주문 금액, 발급 가능 기간, 사용 가능 기간을 담는다. 이것은 회원 누구에게도 속하지 않은 **틀**이며, 원장이 하나 있어도 아무도 그 쿠폰을 갖고 있지 않을 수 있다.

**회원이 보유한 쿠폰**은 그 틀에서 특정 회원에게 발급된 실물 한 장이다. 누구의 것인지, 어느 쿠폰 원장에서 나왔는지, 아직 안 썼는지 이미 썼는지, 썼다면 언제 썼는지, 언제까지 쓸 수 있는지를 담는다. 회원의 쿠폰함에 보이는 것이 바로 이것이다.

**할인 방식**은 두 가지다.

| 할인 방식 | 계산 방법 | 최대 할인 금액 |
|---|---|---|
| 정액 할인 | 정해진 금액을 그대로 깎는다(예: 5,000원) | 해당 없음 |
| 정률 할인 | 주문 금액의 정해진 비율을 깎는다(예: 10%) | 상한을 정할 수 있고, 상한을 넘으면 상한까지만 깎는다 |

**발급 기간**은 그 쿠폰을 회원에게 나눠 줄 수 있는 기간이고, **사용 기간**은 발급받은 회원이 실제로 쓸 수 있는 기간이다. 이 둘은 별개다. 발급은 1월에만 하지만 사용은 2월 말까지 가능한 쿠폰을 만들 수 있다.

**최소 주문 금액**은 이 쿠폰을 쓰기 위해 주문 금액이 얼마 이상이어야 하는지를 정한 값이다. 지정하지 않으면 0원, 즉 제한이 없다.

**최대 발급 수량**은 관리자가 참고용으로 남기는 값이다. 등록·수정·조회에서 다루지만, 지금 시스템이 발급 시점에 이 숫자를 자동으로 확인해 막지는 않는다. 즉 발급 한도는 시스템이 강제하는 규칙이 아니라 운영자가 관리하는 안내 정보다.

**노출 여부**는 그 쿠폰 원장을 목록에 드러낼지 정하는 값이다. 지정하지 않으면 미노출로 시작한다.

## 주요 업무 흐름

### 관리자가 쿠폰을 만든다

관리자는 쿠폰 이름과 설명을 정하고, 정액 할인인지 정률 할인인지를 고른다. 정액이면 깎을 금액을, 정률이면 깎을 비율을 입력한다. 정률이라면 최대 할인 금액 상한을 함께 정할 수 있다.

이어서 최소 주문 금액, 발급 기간의 시작·종료, 사용 기간의 시작·종료를 지정한다. 사용 종료 일시는 반드시 넣어야 한다 — 회원에게 발급될 때 이 값이 그 회원 쿠폰의 유효기간으로 그대로 넘어가기 때문에, 이 값이 비면 발급된 쿠폰이 언제 만료되는지 판단할 수 없게 된다.

등록 시점에 시스템은 값이 앞뒤가 맞는지 확인한다. 정률인데 비율이 1%보다 작거나 100%보다 크면 등록되지 않고, 정액인데 금액이 1원보다 작으면 등록되지 않는다. 최대 할인 금액이나 최소 주문 금액이 음수여도 거부된다. 발급 기간과 사용 기간 각각에서 시작이 종료보다 늦어도 거부된다. 이 확인은 등록할 때만이 아니라 수정할 때도 똑같이 이루어진다 — 등록만 막고 수정을 열어 두면 같은 잘못된 값이 뒷문으로 들어오기 때문이다.

### 관리자가 쿠폰을 회원에게 발급한다

관리자는 만들어 둔 쿠폰을 골라 특정 회원에게 발급한다. 발급되면 그 회원의 쿠폰함에 쿠폰 한 장이 생기며, 유효기간은 쿠폰 원장의 사용 종료 일시를 그대로 물려받는다.

같은 쿠폰을 같은 회원에게 두 번 발급할 수는 없다. 이미 갖고 있는 회원에게 다시 발급하려 하면 이미 발급된 쿠폰이라는 안내를 받고 아무것도 늘어나지 않는다. 즉 한 회원은 한 쿠폰 원장에서 최대 한 장만 가진다.

관리자는 특정 쿠폰의 발급 현황도 확인할 수 있어, 누가 받았고 누가 썼는지를 목록으로 본다.

### 회원이 쿠폰함을 본다

회원은 자기 쿠폰함에서 보유한 쿠폰 전체를 본다. 여기에는 아직 안 쓴 것, 이미 쓴 것, 기간이 지난 것이 모두 포함된다. 어떤 쿠폰을 언제 썼는지 되짚어 볼 수 있게 하기 위함이다.

주문 화면에서 쿠폰을 고를 때는 **지금 쓸 수 있는 쿠폰만** 보인다. 이미 쓴 쿠폰과 유효기간이 지난 쿠폰은 목록에서 빠지므로, 회원이 쓸 수 없는 쿠폰을 골라 실패하는 일이 줄어든다.

### 회원이 주문에서 쿠폰을 쓴다

회원은 주문할 때 쿠폰을 하나 골라 적용한다. 이때 벌어지는 일은 다음 순서다.

먼저 그 쿠폰이 정말 본인의 것인지 확인한다. 다른 사람의 쿠폰이면 권한이 없다는 안내를 받고 주문이 진행되지 않는다. 다음으로 그 쿠폰이 아직 쓸 수 있는 상태인지 확인한다. 이미 썼거나 기간이 지났으면 사용할 수 없는 쿠폰이라는 안내를 받는다.

그다음 최소 주문 금액을 확인한다. 이때 비교 대상은 상품 자체 할인까지 적용된 금액이다. 상품 할인 후 금액이 쿠폰의 최소 주문 금액에 미달하면 최소 주문 금액을 채우지 못했다는 안내를 받고 주문이 진행되지 않는다.

모두 통과하면 할인액을 계산한다. 정액이면 정해진 금액, 정률이면 상품 할인 후 금액에 비율을 적용한 값이며, 상한이 있으면 상한을 넘지 않는다. 그리고 그 회원 쿠폰이 사용 완료 상태로 바뀌면서 사용 시각이 기록된다.

산출된 할인액은 그대로 주문 금액 계산에 쓰인다. 시스템은 회원이 화면에서 본 쿠폰 할인액과 서버가 계산한 할인액이 같은지 대조하며, 다르면 쿠폰 할인 금액이 맞지 않는다는 안내를 내고 주문을 진행하지 않는다. 화면에 표시된 금액과 실제 결제 금액이 어긋나는 것을 막기 위한 확인이다.

쿠폰 사용 처리와 주문 접수는 하나의 묶음으로 처리되므로, 주문이 실패하면 쿠폰이 쓰인 것으로 남지 않고 다시 쓸 수 있는 상태로 되돌아간다.

### 관리자가 쿠폰을 지운다

쿠폰 원장 삭제는 실제로 지우는 것이 아니라 삭제된 것으로 표시하는 방식이다. 삭제 표시된 쿠폰은 관리자 쿠폰 목록과 상세 조회에서 모두 빠진다.

여기서 주의할 점이 있다. 쿠폰 원장을 삭제해도 **이미 회원에게 발급된 쿠폰은 회원 쿠폰함에서 사라지지 않는다.** 회원이 보유한 쿠폰은 별개의 것이기 때문이다. 따라서 배포를 그만두고 싶은 쿠폰은 삭제하되, 이미 나간 쿠폰이 계속 쓰일 수 있다는 점을 감안해야 한다.

## 상태와 전이 규칙

### 쿠폰 원장

| 상태 | 의미 | 관리자 목록 |
|---|---|---|
| 노출 | 목록에 드러나는 정상 상태 | 보인다 |
| 미노출 | 준비 중이거나 내린 상태(등록 시 기본값) | 보인다 |
| 삭제됨 | 삭제 표시된 상태 | 보이지 않는다 |

| 전이 | 실행 주체 | 설명 |
|---|---|---|
| 등록 | 관리자 | 노출 여부를 지정하지 않으면 미노출로 시작 |
| 노출 ↔ 미노출 | 관리자 | 쿠폰 수정 시 함께 변경 |
| 삭제됨 | 관리자 | 이미 발급된 회원 쿠폰에는 영향이 없다 |

### 회원이 보유한 쿠폰

| 상태 | 의미 | 사용 가능 여부 |
|---|---|---|
| 사용 가능 | 발급되었고 아직 쓰지 않았으며 유효기간이 남은 상태 | 쓸 수 있다 |
| 사용 완료 | 주문 결제에 쓴 상태. 사용 시각이 함께 기록된다 | 쓸 수 없다 |
| 기간 만료 | 유효기간이 지난 상태 | 쓸 수 없다 |

| 전이 | 계기 | 설명 |
|---|---|---|
| (없음) → 사용 가능 | 관리자 발급 | 유효기간은 쿠폰 원장의 사용 종료 일시를 물려받는다 |
| 사용 가능 → 사용 완료 | 회원의 주문 결제 | 되돌릴 수 없다 |
| 사용 가능 → 기간 만료 | 유효기간 경과 | 별도 조작 없이 시간이 지나면 자동으로 쓸 수 없게 된다 |

기간 만료는 누가 처리하는 상태 변경이 아니라, 유효기간과 현재 시각을 비교해 판단되는 결과다. 만료 처리 작업이 따로 돌지 않아도 기간이 지나면 쓸 수 없다. 유효기간 정보가 아예 없는 옛 쿠폰은 무기한으로 간주해 만료로 보지 않는다 — 기간 정보가 없다는 이유로 정상 발급된 쿠폰을 못 쓰게 막지 않으려는 판단이다.

## 비즈니스 규칙

| 규칙 | 위반 시 사용자에게 일어나는 일 |
|---|---|
| 정률 할인의 비율은 1% 이상 100% 이하여야 한다 | 관리자가 범위를 벗어난 비율로 등록·수정하려 하면 할인율이 올바르지 않다는 안내를 받고 저장되지 않는다 |
| 정액 할인의 금액은 1원 이상이어야 한다 | 0원 이하로 등록·수정하려 하면 할인 금액이 올바르지 않다는 안내를 받고 저장되지 않는다 |
| 최대 할인 금액과 최소 주문 금액은 음수일 수 없다 | 음수로 등록·수정하려 하면 금액이 올바르지 않다는 안내를 받고 저장되지 않는다 |
| 사용 종료 일시는 반드시 지정해야 한다 | 비워 두면 사용 종료 일시가 필요하다는 안내를 받는다. 이 값이 발급된 쿠폰의 유효기간이 되기 때문이다 |
| 발급 기간·사용 기간 각각에서 시작이 종료보다 늦을 수 없다 | 순서가 뒤바뀌면 기간이 올바르지 않다는 안내를 받고 저장되지 않는다 |
| 등록 시와 수정 시 같은 검증을 적용한다 | 등록에서 막힌 값은 수정으로도 넣을 수 없다 |
| 할인 방식은 정액·정률 중 하나여야 한다 | 알 수 없는 값을 보내면 잘못된 할인 유형이라는 안내를 받는다 |
| 발급할 쿠폰 원장이 존재해야 한다 | 없는 쿠폰을 발급하려 하면 쿠폰을 찾을 수 없다는 안내를 받는다 |
| 한 회원은 같은 쿠폰을 두 번 발급받을 수 없다 | 이미 보유한 회원에게 다시 발급하려 하면 이미 발급된 쿠폰이라는 안내를 받고 쿠폰이 늘어나지 않는다 |
| 쿠폰은 본인 것만 쓸 수 있다 | 다른 사람의 쿠폰을 쓰려 하면 권한이 없다는 안내를 받고 주문이 진행되지 않는다 |
| 이미 썼거나 기간이 지난 쿠폰은 쓸 수 없다 | 사용할 수 없는 쿠폰이라는 안내를 받고 주문이 진행되지 않는다 |
| 상품 할인 후 주문 금액이 쿠폰의 최소 주문 금액을 넘어야 한다 | 최소 주문 금액을 채우지 못했다는 안내를 받고 주문이 진행되지 않는다 |
| 정률 할인은 최대 할인 금액 상한을 넘지 않는다 | 계산값이 상한보다 크면 상한까지만 할인된다. 상한을 정하지 않았으면 제한 없이 계산값대로 할인된다 |
| 화면에 표시된 쿠폰 할인액과 서버 계산액이 일치해야 한다 | 다르면 쿠폰 할인 금액이 맞지 않는다는 안내를 받고 주문이 진행되지 않는다 |
| 쿠폰 사용과 주문 접수는 함께 처리된다 | 주문이 실패하면 쿠폰이 사용 완료로 남지 않고 다시 쓸 수 있는 상태로 되돌아간다 |
| 쿠폰 원장 삭제는 이미 발급된 회원 쿠폰에 영향을 주지 않는다 | 관리자가 쿠폰을 삭제해도 이미 받은 회원은 계속 쓸 수 있다. 배포 중단과 회수는 별개의 일이다 |
| 최대 발급 수량은 시스템이 강제하지 않는다 | 지정한 수량을 넘겨도 발급이 자동으로 막히지 않는다. 발급 현황을 보고 운영자가 관리해야 한다 |

## 다른 도메인과의 관계

**주문** — 쿠폰이 실제로 쓰이는 유일한 지점이다. 주문을 접수할 때 쿠폰 사용 처리와 할인액 계산이 주문 금액 계산의 일부로 함께 일어난다. 쿠폰 할인액은 상품 자체 할인이 적용된 뒤의 금액을 기준으로 계산되며, 포인트 사용과 함께 최종 결제 금액을 결정한다. 주문이 실패하면 쿠폰 사용도 취소된다.

**회원** — 발급된 쿠폰은 항상 특정 회원에게 귀속된다. 회원은 자기 쿠폰만 보고 쓸 수 있으며, 쿠폰함은 내 정보 화면의 일부로 제공된다.

**포인트** — 주문에서 쿠폰 할인과 포인트 사용은 나란히 적용되는 별개의 할인 수단이다. 서로 대체하는 관계가 아니라 함께 쌓여 최종 결제 금액을 줄인다.

**이벤트/프로모션** — 쿠폰은 원칙적으로 이벤트 보상이나 가입 보상으로 자동 발급될 수 있는 구조를 갖추고 있으나, 현재 쿠폰이 실제로 발급되는 경로는 관리자의 수동 발급 하나다. 가입·추천 등에 따른 자동 발급은 아직 연결되어 있지 않다.

## 사용자별 접점

### 일반 회원(웹)

- 내 쿠폰함에서 보유한 쿠폰 전체를 본다(사용 완료·기간 만료 포함).
- 주문 화면에서 지금 쓸 수 있는 쿠폰만 골라 본다.
- 주문할 때 쿠폰을 적용해 할인을 받는다.

회원이 직접 쿠폰을 받아 가는 화면(다운로드·응모)은 현재 제공되지 않는다. 쿠폰은 관리자가 발급해 준 것을 보유하는 형태다.

### 관리자

- 쿠폰 목록을 조회한다. 할인 유형·이름 부분 검색·노출 여부로 걸러 볼 수 있고, 삭제된 쿠폰은 목록에서 빠진다.
- 쿠폰을 등록한다(이름·설명·할인 방식·할인값·최대 할인 금액·최소 주문 금액·최대 발급 수량·발급 기간·사용 기간·노출 여부).
- 쿠폰 상세를 조회하고 수정한다.
- 쿠폰을 삭제한다(삭제 표시 방식이며 이미 발급된 회원 쿠폰은 유지된다).
- 특정 회원에게 쿠폰을 수동 발급한다.
- 특정 쿠폰의 회원 발급 현황을 조회한다.

### 점주

쿠폰 도메인에는 점주 전용 접점이 없다. 쿠폰은 서비스 전체 차원의 할인 수단으로 관리자가 운영하며, 점주가 자기 가게 전용 쿠폰을 만들거나 발급하는 기능은 제공되지 않는다.

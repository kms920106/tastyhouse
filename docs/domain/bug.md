# 버그 신고(bug) 도메인

## 이 도메인은 무엇인가

회원이 서비스를 쓰다가 겪은 오류나 이상 동작을 직접 알릴 수 있는 창구다. 회원은 어떤 문제가 생겼는지 제목과 내용으로 적고, 화면 사진을 첨부하고, 자신이 쓰는 기기 정보를 함께 남긴다. 접수된 신고는 관리자가 확인해 분류하고 우선순위를 정하고 담당자를 배정한 뒤, 처리 결과를 기록하며 마무리한다.

회원이 신고를 등록하는 것과 관리자가 그것을 처리하는 것이 뚜렷하게 나뉘어 있는 구조다. 회원은 등록만 하고, 이후 분류·처리는 전부 관리자 쪽에서 이루어진다.

## 핵심 개념

**버그 신고**
회원이 제보한 문제 한 건이다. 담고 있는 정보는 크게 세 갈래다.

*제보자가 입력하는 정보*
- 기기 정보 — 어떤 단말기에서 겪었는지 (필수, 100자 이내)
- 제목 — 문제를 한 줄로 (필수, 200자 이내)
- 내용 — 상세한 상황 설명 (필수)
- 앱 버전, 플랫폼(iOS·안드로이드), 운영체제 버전 — 모두 선택 입력
- 첨부 이미지 — 최대 5장

*관리자가 채우는 정보*
- 분류 — 어떤 영역의 문제인지
- 우선순위 — 얼마나 급한 문제인지
- 담당자 — 어느 관리자가 처리하는지
- 처리 결과 또는 반려 사유
- 처리 완료 일시

*시스템이 남기는 정보*
- 제보한 회원, 접수 일시, 최종 수정 일시

접수 직후에는 관리자가 채우는 항목이 모두 비어 있다. 분류도 우선순위도 담당자도 정해지지 않은 "미분류" 상태로 목록에 들어온다.

**첨부 이미지**
신고에 딸린 화면 사진이다. 최대 5장까지 첨부할 수 있고, **회원이 올린 순서가 그대로 보존된다.** 관리자 상세 화면에서 그 순서대로 보인다.

**분류**
문제가 어느 영역에서 발생했는지를 나타낸다. 일곱 가지가 있다.

| 분류 | 어떤 문제 |
|---|---|
| 결제 | 결제 진행·승인·취소 관련 |
| 로그인 | 로그인·인증 관련 |
| 주문 | 주문 접수·조회 관련 |
| 예약 | 가게 예약 관련 |
| 화면 | 화면 표시가 깨지거나 잘못 보이는 문제 |
| 성능 | 느림·멈춤 등 속도 문제 |
| 기타 | 위 어디에도 속하지 않는 문제 |

**우선순위**
처리 시급성을 네 단계로 나눈다.

| 우선순위 | 의미 |
|---|---|
| 낮음 | 급하지 않음 |
| 보통 | 일반적인 처리 순서 |
| 높음 | 우선 처리 필요 |
| 심각 | 서비스에 중대한 장애를 일으키는 문제 |

## 주요 업무 흐름

### 회원의 신고 등록

회원이 앱·웹의 문의·신고 화면에서 버그를 제보한다. 사진을 첨부하려면 먼저 이미지를 올려두고, 그 결과를 신고 내용과 함께 저장한다.

등록하면 **신고와 첨부 이미지가 한 묶음으로 저장된다.** 신고는 저장되었는데 사진이 누락되거나, 사진만 남고 신고가 없는 상태가 생기지 않는다. 이미지는 회원이 올린 순서대로 번호가 부여되어 보관된다.

등록 직후 신고 상태는 "접수"이고, 회원은 등록되었다는 확인만 받는다. **회원이 자기 신고의 처리 상태나 관리자 답변을 조회하는 화면은 현재 없다.** 등록이 회원 쪽 접점의 전부다.

### 관리자의 확인과 분류

관리자는 관리자 화면에서 접수된 신고 목록을 확인한다. 제목이나 내용의 일부 단어로 검색할 수 있고, 특정 회원이 올린 신고만 골라 볼 수 있으며, 목록은 페이지 단위로 나뉘어 표시된다.

상세 화면을 열면 제보자가 입력한 모든 정보와 첨부 사진, 그리고 제보한 회원의 정보가 함께 보인다.

관리자는 신고를 읽고 두 가지를 정한다.

- **분류와 우선순위 지정** — 어떤 영역의 문제이고 얼마나 급한지를 함께 지정한다. 둘은 한 번에 지정되며, 나중에 판단이 바뀌면 **몇 번이든 다시 지정할 수 있다.** 처리가 진행 중이든 이미 끝났든 재분류가 가능하다.
- **담당자 배정** — 처리를 맡을 관리자를 지정한다. 역시 언제든 다시 배정할 수 있다.

분류·우선순위·담당자 지정은 처리 상태와 무관하게 이루어진다. 즉 분류하지 않고도 바로 처리를 시작할 수 있고, 처리가 끝난 뒤에 분류를 정리할 수도 있다.

### 처리와 마무리

관리자는 신고의 처리 상태를 바꿔가며 진행 상황을 기록한다.

**처리 시작** — 담당자가 확인해 대응에 들어가면 "처리중"으로 바꾼다.

**보류** — 외부 서비스 응답을 기다려야 하거나 다음 릴리스에 반영할 사안이면 "보류"로 둔다. 나중에 다시 "처리중"으로 되돌려 진행할 수 있다.

**처리 완료** — 문제를 고쳤으면 "처리완료"로 바꾸며 이때 **처리 결과를 함께 기록한다.** 예를 들어 어느 버전에서 수정되었는지를 적는다. 완료 시각도 자동으로 남는다.

**반려** — 재현되지 않거나 정상 동작으로 확인되면 "반려"로 처리하며 **반려 사유를 기록한다.** 종결 시각도 함께 남는다.

"처리완료"와 "반려"는 종결 상태이므로 여기서 다른 상태로 바뀌지 않는다. 또한 어떤 상태에서든 처음의 "접수"로 되돌릴 수는 없다.

## 상태와 전이 규칙

| 상태 | 의미 |
|---|---|
| 접수 | 회원이 등록한 직후의 첫 상태 |
| 처리중 | 담당자가 확인해 대응하고 있음 |
| 처리완료 | 수정·조치가 끝남. 처리 결과와 완료 시각이 기록됨 |
| 반려 | 재현 불가·정상 동작 등으로 처리하지 않음. 사유와 종결 시각이 기록됨 |
| 보류 | 외부 의존이나 후속 릴리스 대기 등으로 잠시 멈춤 |

| 어떤 상태에서 | 어떤 동작으로 | 어떤 상태로 | 함께 기록되는 것 |
|---|---|---|---|
| 접수 | 처리 시작 | 처리중 | — |
| 접수 | 보류 | 보류 | — |
| 접수 | 처리 완료 | 처리완료 | 처리 결과, 완료 시각 |
| 접수 | 반려 | 반려 | 반려 사유, 종결 시각 |
| 처리중 | 보류 | 보류 | — |
| 처리중 | 처리 완료 | 처리완료 | 처리 결과, 완료 시각 |
| 처리중 | 반려 | 반려 | 반려 사유, 종결 시각 |
| 보류 | 처리 시작 | 처리중 | — |
| 보류 | 처리 완료 | 처리완료 | 처리 결과, 완료 시각 |
| 보류 | 반려 | 반려 | 반려 사유, 종결 시각 |

정리하면 이렇다.

- **접수·처리중·보류** 사이는 비교적 자유롭게 오갈 수 있다. 단 "처리중"에서 다시 "접수"로 돌아가는 것은 안 되고, "보류"에서 "처리중"으로 재개하는 경로는 열려 있다
- **처리완료·반려**는 종결이며 여기서 나오는 경로가 없다
- **접수로 되돌리는 경로는 어디에도 없다**

분류·우선순위·담당자 지정은 위 표와 무관하게 어떤 상태에서든 몇 번이든 가능하다.

## 비즈니스 규칙

**기기 정보·제목·내용은 반드시 입력해야 한다**
비워 두면 등록되지 않고 각각 "단말기 정보는 필수입니다", "제목은 필수입니다", "내용은 필수입니다"라는 안내가 나온다. 기기 정보는 100자, 제목은 200자를 넘길 수 없다.

**앱 버전·플랫폼·운영체제 버전은 선택이다**
입력하지 않아도 등록된다. 앱 버전과 운영체제 버전은 각각 30자 이내여야 한다. 플랫폼은 iOS와 안드로이드 둘 중 하나만 지정할 수 있으며, 그 밖의 값을 넘기면 "알 수 없는 버그 제보 플랫폼입니다"라는 안내가 나온다.

**사진은 최대 5장까지다**
5장을 넘겨 첨부하면 "사진은 최대 5장까지 첨부할 수 있습니다"라는 안내가 나온다. 첨부 없이도 등록할 수 있다.

**첨부 순서는 보존된다**
회원이 올린 순서가 그대로 관리자 화면의 표시 순서가 된다.

**종결된 신고는 다시 처리할 수 없다**
이미 "처리완료" 또는 "반려"된 신고의 상태를 바꾸려 하면 "현재 상태에서는 해당 처리를 할 수 없습니다"라는 안내가 나온다.

**접수 상태로는 되돌릴 수 없다**
어떤 상태에서든 처음의 "접수"로 되돌리는 요청은 "현재 상태에서는 해당 처리를 할 수 없습니다"로 거부된다.

**처리중에서 처리 시작을 다시 할 수는 없다**
이미 "처리중"인 신고를 다시 "처리중"으로 바꾸려 하면 거부된다. 마찬가지로 이미 "보류"인 신고를 다시 "보류"로 바꿀 수도 없다.

**정해진 분류·우선순위 값만 쓸 수 있다**
분류 일곱 가지, 우선순위 네 가지 외의 값을 넘기면 각각 "알 수 없는 버그 제보 분류입니다", "알 수 없는 버그 제보 우선순위입니다"라는 안내가 나온다.

**없는 신고는 처리할 수 없다**
존재하지 않는 신고를 조회하거나 처리하려 하면 "버그 제보를 찾을 수 없습니다"라는 안내가 나온다.

**처리 결과와 반려 사유는 종결 시점에만 기록된다**
처리 완료나 반려로 넘어갈 때 입력한 내용이 기록되며, "처리중"이나 "보류"로 바꿀 때는 기록되지 않는다.

## 다른 도메인과의 관계

**회원**
모든 신고에는 제보한 회원이 연결된다. 관리자 상세 화면에서 그 회원의 정보를 함께 볼 수 있고, 특정 회원의 신고만 골라 조회할 수도 있다. 신고 등록은 로그인한 회원만 할 수 있다.

**파일**
첨부 사진은 파일 도메인에 먼저 올려둔 이미지를 가리킨다. 신고 자체는 사진을 갖지 않고 어떤 이미지를 쓸지만 연결해 둔다. 관리자 화면에 필요한 이미지 주소는 조회 시점에 만들어져 함께 전달된다. 사진 첨부 규칙(허용 형식·용량 한도)은 파일 도메인의 공통 규칙을 따른다.

**관리자 계정**
담당자로 배정되는 대상은 관리자 계정이다. 배정 자체가 그 관리자에게 별도 권한을 부여하는 것은 아니며, 누가 담당하는지를 기록해 두는 역할이다.

**분류가 가리키는 도메인들**
분류 항목(결제·로그인·주문·예약·화면·성능)은 실제 도메인 이름과 겹치지만 시스템적으로 연결되어 있지는 않다. 예를 들어 "예약" 분류로 지정된 신고가 특정 예약 건과 연결되는 것은 아니다. 어느 영역의 문제인지를 사람이 판단해 붙이는 꼬리표에 가깝다.

## 사용자별 접점

**일반 회원(웹)**
- 버그 신고 등록 (기기 정보·제목·내용 필수, 앱 버전·플랫폼·운영체제 버전 선택, 사진 최대 5장)

회원은 등록만 할 수 있고, 자기 신고의 처리 상태나 관리자 답변을 확인하는 화면은 없다.

**관리자**
- 신고 목록 조회 (제목·내용 부분 검색, 특정 회원 필터, 페이지 단위)
- 신고 상세 조회 (제보 내용, 첨부 사진, 제보 회원 정보)
- 처리 상태 변경 (처리중·처리완료·반려·보류 / 완료·반려 시 결과 기록)
- 분류와 우선순위 지정
- 담당자 배정

**점주**
버그 신고를 다루는 점주 화면은 없다.

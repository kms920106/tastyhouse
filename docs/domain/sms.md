# 휴대폰번호 인증(sms) 도메인

## 이 도메인은 무엇인가

휴대폰번호 인증 도메인은 "이 휴대폰번호가 정말 본인 것인가"를 확인하는 절차를 담당한다. 서비스가 여섯 자리 인증번호를 문자로 보내고, 사용자가 받은 번호를 입력하면 그 번호의 주인임이 확인된다.

이메일 인증 도메인과 구조가 거의 같다. 다른 점은 전달 수단이 메일이 아니라 문자라는 것, 그리고 용도별 문구 구분 없이 하나의 문구만 쓴다는 것이다.

## 핵심 개념

**인증번호** — 여섯 자리 숫자로 자동 생성된다.

**유효시간** — 발급 시점부터 5분이다. 문자 문구에도 같은 5분이 안내되므로 실제 만료 시간과 안내가 어긋나지 않는다.

**휴대폰번호 형식** — 국내 휴대폰번호 형식이어야 하며, 하이픈 없이 숫자만 받는다.

**인증 상태** — 확인 대기, 인증 완료, 만료 세 가지다.

## 주요 업무 흐름

사용자가 휴대폰번호를 입력하고 인증번호 발송을 요청한다. 서비스는 먼저 같은 번호로 앞서 발급했던, 아직 확인되지 않은 인증번호를 모두 만료시킨다. 발송 버튼을 여러 번 눌렀을 때 옛 번호가 계속 살아 있으면 안 되기 때문이며, 이 처리 덕분에 언제나 가장 최근에 받은 문자의 번호만 유효하다. 그다음 새 인증번호를 만들어 저장하고, 곧바로 그 번호를 담은 문자를 보낸다.

**여기서 이 도메인의 가장 중요한 규칙이 나온다. 인증번호를 만들어 두는 일과 실제로 문자를 보내는 일은 항상 함께 처리된다.** 과거에는 이 두 가지가 분리되어 있어서, 인증번호는 시스템에 저장됐지만 문자는 실제로 나가지 않는 일이 있었다. 사용자는 "발송되었습니다"라는 응답을 받고 문자를 기다리는데 아무것도 오지 않는 상황이다. 실제로 문자 발송 기능은 한동안 한 번도 동작하지 않은 상태였다. 그래서 지금은 둘을 붙여서 처리한다. 문자 발송이 실패하면 인증번호도 남지 않고 사용자에게 실패했다는 응답이 간다. 인증번호는 사용자에게 전달되지 않으면 아무 가치가 없으므로, "번호는 있는데 문자는 오지 않은" 어중간한 상태로 남기는 대신 아예 실패로 처리하는 편이 옳다. 운영·QA 관점에서는 "발송 성공 응답을 받았다면 문자는 반드시 나갔다"고 믿을 수 있다는 뜻이 된다.

사용자가 문자에서 번호를 확인해 입력하면 확인 절차가 진행된다. 그 번호로 발급된 확인 대기 상태의 인증번호를 찾아, 만료되지 않았는지 보고 번호가 맞는지 대조한다. 둘 다 통과하면 인증 완료로 바뀌고 확인 시각이 기록된다.

인증이 완료되면 사용자는 짧은 시간 동안 유효한 인증 증표를 받는다. 개인정보 수정 화면에서 휴대폰번호를 바꿀 때 이 증표를 함께 보내야 하므로, 인증을 거치지 않고 남의 번호로 바꿔치기하는 것이 불가능하다.

## 상태와 전이 규칙

| 상태 | 의미 |
| --- | --- |
| 확인 대기 | 인증번호가 발급되어 문자로 나갔고 아직 확인되지 않은 상태다. 발급 직후의 상태다. |
| 인증 완료 | 사용자가 올바른 번호를 유효시간 안에 입력해 확인된 상태다. |
| 만료 | 더 이상 쓸 수 없는 상태다. |

만료가 되는 경우는 두 가지다. 하나는 유효시간 5분이 지난 뒤 번호를 입력했을 때이고, 다른 하나는 같은 휴대폰번호로 새 인증번호를 발급받아 이전 번호가 밀려났을 때다.

## 비즈니스 규칙

| 규칙 | 위반하면 어떻게 되는가 |
| --- | --- |
| 휴대폰번호 형식이 맞아야 한다 | 형식이 어긋나면 올바른 휴대폰번호 형식이 아니라는 안내가 나오고 발송되지 않는다. |
| 인증번호는 발급 후 5분 안에 입력해야 한다 | 5분이 지나 입력하면 만료되었다는 안내가 나오고, 그 번호는 만료 처리된다. 다시 발송을 요청해야 한다. |
| 인증번호는 정확히 일치해야 한다 | 틀리면 번호가 일치하지 않는다는 안내가 나온다. 이 경우 번호는 만료되지 않으므로 유효시간 안에 다시 입력할 수 있다. |
| 같은 번호로 새 인증번호를 받으면 이전 번호는 못 쓴다 | 옛 문자에 적힌 번호를 입력하면 일치하지 않는다는 안내가 나온다. 가장 마지막에 받은 문자의 번호를 써야 한다. |
| 발급된 번호가 없으면 확인할 수 없다 | 발송 요청을 한 적이 없거나 이미 처리된 상태에서 확인을 시도하면 인증번호를 찾을 수 없다는 안내가 나온다. |
| 같은 휴대폰번호로 하루에 다섯 번까지만 발송을 요청할 수 있다 | 여섯 번째 요청은 막힌다. 24시간이 지나면 다시 요청할 수 있다. 남의 번호로 문자를 무한정 보내는 것과, 번호를 무작위로 찍어 맞히려는 시도를 함께 막는 목적이다. 문자는 발송할 때마다 비용이 들기 때문에 비용 관점에서도 필요한 제한이다. |
| 문자 발송이 실패하면 인증번호도 남지 않는다 | 사용자는 실패 응답을 받는다. 다시 요청하면 새 번호가 발급되고 발송이 다시 시도된다. |

인증 완료 후 받는 증표는 10분 동안만 유효하다. 인증만 하고 화면을 오래 방치하면 다시 인증해야 한다.

이메일 인증과 달리, 이 도메인에는 "이미 등록된 번호인지" 미리 확인하는 절차가 없다. 즉 다른 회원이 이미 쓰고 있는 휴대폰번호로도 인증번호를 받을 수 있고, 중복 여부는 실제로 번호를 바꾸는 시점에 판단된다.

## 다른 도메인과의 관계

**회원** — 개인정보에서 휴대폰번호를 바꿀 때 이 인증을 거친다. 인증 증표 없이는 번호 변경이 통과되지 않는다.

**이메일 인증** — 구조가 똑같은 자매 도메인이다. 발급 방식, 유효시간 5분, 하루 다섯 번 제한, 발급과 발송을 함께 처리하는 규칙이 모두 같다. 회원가입에는 이메일 인증이, 휴대폰번호 변경에는 이 인증이 쓰인다.

## 사용자별 접점

**일반 회원(웹)** — 개인정보 수정 화면에서 휴대폰번호를 바꿀 때 인증을 거친다. 보이는 것은 "인증번호 발송" 버튼과 번호 입력란, 그리고 도착하는 인증 문자다.

**관리자** — 이 인증을 쓰지 않는다. 인증 발급 이력을 조회하는 관리 화면도 없다.

**점주** — 지금은 점주 화면에서 휴대폰번호 인증을 쓰지 않는다. 다만 앞으로 점주 화면이 이 기능을 함께 쓸 것을 전제로 설계되어 있어, 그때도 인증 규칙은 같게 유지된다.

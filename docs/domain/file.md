# 파일(file) 도메인

## 이 도메인은 무엇인가

서비스에서 사용하는 모든 이미지를 저장하고 관리하는 공통 기반이다. 회원이 리뷰에 올리는 사진, 점주가 등록하는 가게 사진, 관리자가 만드는 이벤트·배너 이미지가 모두 이곳을 거쳐 저장된다.

특징은 **다른 도메인이 이미지 자체를 갖지 않는다**는 점이다. 이미지는 먼저 이 도메인에 올려 보관하고, 각 도메인은 "어떤 이미지를 쓸지"만 연결해 둔다. 덕분에 허용 형식이나 용량 한도 같은 규칙이 화면마다 달라지지 않고 한 곳에서 통일된다.

## 핵심 개념

**업로드된 파일**
저장된 이미지 한 건의 기록이다. 다음 정보를 갖는다.

- 원래 파일 이름 — 이용자가 올릴 때의 이름 그대로 보관한다
- 저장 이름 — 서비스가 새로 부여한 고유한 이름
- 저장 위치 — 실제 보관 장소에서의 경로
- 파일 크기와 파일 형식

**저장 이름과 저장 위치**
서비스는 올라온 파일을 원래 이름으로 저장하지 않는다. 겹치지 않는 고유한 이름을 새로 만들어 붙이고, 업로드한 **날짜별 폴더**(연/월/일)에 나누어 보관한다. 이렇게 하면 같은 이름의 파일을 여러 명이 올려도 서로 덮어쓰지 않고, 날짜별로 정리되어 관리도 쉬워진다. 원래 이름은 기록으로만 남는다.

**표시용 이미지 주소**
화면에 이미지를 띄우려면 인터넷에서 접근할 수 있는 주소가 필요하다. 이 주소는 저장 위치를 바탕으로 **서버가 만들어 준다.** 저장 위치 자체를 그대로 주소로 쓸 수는 없기 때문이다. 이 주소는 데이터로 저장해 두지 않고 화면에 내려줄 때마다 그때그때 만들어진다.

**보관 장소**
실제 이미지 파일은 서비스 데이터베이스가 아니라 외부 저장 서비스에 보관된다. 어느 저장 서비스를 쓸지는 운영 설정으로 정해지며, 서비스의 나머지 부분은 그 차이를 알지 못하고 동작한다.

## 주요 업무 흐름

### 업로드

이용자가 화면에서 이미지를 선택해 올리면 다음 순서로 처리된다.

1. **검증** — 파일이 비어 있지 않은지, 용량이 한도 안인지, 허용된 형식과 확장자인지 확인한다
2. **저장 이름 부여** — 겹치지 않는 고유한 이름을 새로 만들고, 오늘 날짜의 폴더 경로를 정한다
3. **보관** — 외부 저장 서비스에 실제 파일을 올린다
4. **기록** — 원래 이름, 저장 이름, 저장 위치, 크기, 형식을 기록으로 남긴다
5. **결과 반환** — 방금 저장된 파일의 식별 번호를 돌려준다

이 다섯 단계는 **한 묶음으로 처리된다.** 중간에 어느 단계라도 실패하면 앞선 처리도 되돌려지므로, 파일은 올라갔는데 기록이 없거나 기록만 있고 파일이 없는 상태가 남지 않는다.

업로드가 끝나면 서비스 내부에 "파일이 올라왔다"는 알림이 남는다. 이 알림은 나중에 업로드 현황 집계 같은 부가 기능을 붙이기 위한 통로이며, 업로드 결과 자체에는 영향을 주지 않는다.

### 다른 도메인이 이미지를 사용하는 방식

이미지를 쓰는 화면은 두 단계로 동작한다.

**1단계 — 먼저 올린다.** 이용자가 이미지를 선택하면 그 즉시 파일 업로드가 이루어지고, 화면은 저장된 파일의 식별 번호를 받아 갖고 있는다.

**2단계 — 그 번호를 함께 저장한다.** 이용자가 최종 저장 버튼을 누르면, 각 도메인은 입력한 내용과 함께 이 번호를 저장한다. 예를 들어 이벤트를 등록할 때는 썸네일과 배너 이미지의 번호를, 버그 신고를 등록할 때는 첨부 이미지들의 번호를 함께 넘긴다.

따라서 **이미지를 선택했더라도 최종 저장을 하지 않으면 그 이미지는 어디에도 연결되지 않은 채 남는다.** 업로드 자체는 이미 완료된 상태다.

### 화면에 이미지가 표시되는 방식

이미지를 화면에 보여줄 때, 각 도메인은 파일 식별 번호를 화면에 내려보내지 않는다. 대신 **조회하는 시점에 표시용 주소를 만들어 그 주소를 내려준다.**

이렇게 하는 이유는 두 가지다.

- 화면 쪽에서 번호만으로는 이미지 주소를 알아낼 방법이 없다. 주소를 만드는 규칙은 보관 장소마다 다르고 운영 설정에 따라 달라지므로 서버만 알 수 있다
- 조회할 때 이미 주소를 함께 가져오므로, 화면을 그리는 도중 이미지 정보를 다시 조회하는 추가 왕복이 생기지 않는다

보관 장소를 바꾸거나 주소 규칙이 변경되어도 저장된 값은 그대로 쓸 수 있다. 저장해 두는 것은 위치 정보이고 주소는 그때그때 만들기 때문이다.

## 상태와 전이 규칙

이 도메인에는 상태 개념이 없다. 파일은 한 번 올라오면 그 기록이 바뀌지 않는다. 이름을 고치거나 내용을 교체하는 기능은 없으며, 이미지를 바꾸고 싶으면 **새로 올려서 새 번호를 연결한다.**

파일 자체를 지우는 화면도 없다. 어떤 도메인에서 이미지를 다른 것으로 바꾸면, 이전 이미지는 그 도메인과의 연결만 끊기고 기록과 실제 파일은 그대로 남는다.

## 비즈니스 규칙

**허용되는 이미지 형식은 네 가지다**
JPG(JPEG), PNG, GIF, WEBP만 올릴 수 있다. 다른 형식을 올리면 "허용되지 않는 파일 형식입니다"라는 안내가 나오고 업로드되지 않는다. 문서·동영상·압축 파일은 올릴 수 없다.

**확장자도 함께 확인한다**
파일 형식과 파일 이름의 확장자를 각각 확인한다. 둘 중 하나라도 허용 목록에 없으면 업로드되지 않는다. 확장자가 없는 파일 이름이면 "파일 확장자를 확인할 수 없습니다"라는 안내가 나온다. 형식과 확장자를 모두 보는 것은 확장자만 바꿔 올리는 우회를 막기 위한 것이다.

**용량은 10MB까지다**
10MB를 넘으면 "파일 크기는 10MB를 초과할 수 없습니다"라는 안내가 나온다.

**빈 파일은 올릴 수 없다**
내용이 없는 파일을 선택하면 "파일이 비어있습니다"라는 안내가 나온다.

**저장에 실패하면 업로드 자체가 실패한다**
외부 저장 서비스 장애 등으로 보관에 실패하면 "파일 저장에 실패했습니다"라는 안내가 나오고, 기록도 남지 않는다. 절반만 처리된 상태가 남지 않는다.

**연결된 이미지를 찾을 수 없으면 알린다**
어떤 도메인이 이미지를 필수로 요구하는 화면에서 연결된 이미지를 찾지 못하면 "파일을 찾을 수 없습니다"라는 안내가 나온다.

**파일 단건 조회 기능은 없다**
번호로 이미지 하나를 직접 불러오는 기능은 제공되지 않는다. 이미지는 항상 그것을 사용하는 도메인의 조회 결과에 주소로 포함되어 전달된다.

## 다른 도메인과의 관계

이 도메인은 서비스에서 가장 널리 참조되는 공통 기반이다. 다음 도메인들이 이미지를 연결해 사용한다.

| 도메인 | 사용하는 이미지 |
|---|---|
| 가게 | 대표 이미지, 상표 이미지, 배너 이미지, 사진 카테고리 이미지, 콘텐츠보드 이미지, 편의정보·음식종류 아이콘, 이미지 변경요청의 신청 이미지 |
| 상품 | 상품 이미지 |
| 리뷰 | 리뷰 첨부 사진 |
| 회원 | 프로필 이미지 |
| 이벤트 | 썸네일 이미지, 배너 이미지 |
| 배너 | 배너 이미지 |
| 버그 신고 | 첨부 이미지 |
| 리뷰 랭킹 | 상품(경품) 이미지 |

이 관계는 **한 방향이다.** 각 도메인이 파일을 참조하지만, 파일 쪽은 어떤 이미지가 어디에 쓰이는지 알지 못한다. 따라서 어떤 이미지가 더 이상 쓰이지 않는지 파일 쪽에서 판단할 수는 없다.

**주문 상품 이미지는 예외다.** 주문 내역에 남는 상품 이미지는 주문한 시점의 이미지 주소를 그대로 복사해 보관한다. 나중에 상품 이미지가 바뀌어도 지난 주문 내역에는 주문 당시의 이미지가 계속 보이도록 하기 위한 것이다.

## 사용자별 접점

**일반 회원(웹)**
- 이미지 업로드 (리뷰 사진, 버그 신고 첨부 등에 앞서 수행)

**관리자**
- 이미지 업로드 (이벤트·배너·가게·상품·경품 이미지 등록에 앞서 수행)

**점주**
- 이미지 업로드 (가게 사진·상표 이미지·콘텐츠보드 이미지 등록에 앞서 수행)

세 이용자 모두 업로드 규칙(허용 형식 네 가지, 최대 10MB)이 동일하다. 다만 가게의 상표·대표 이미지처럼 규격(해상도·비율)이 추가로 정해진 이미지는 가게 도메인 쪽에서 업로드 전에 별도 확인을 거친다.

# 이메일 인증(mail) 도메인

## 이 도메인은 무엇인가

이메일 인증 도메인은 "이 이메일 주소가 정말 본인 것인가"를 확인하는 절차를 담당한다. 회원가입할 때 아무 이메일이나 적고 가입하는 것을 막고, 비밀번호를 잊었을 때 계정 주인만 재설정할 수 있게 하는 장치다.

방식은 흔히 쓰는 인증번호 방식이다. 서비스가 여섯 자리 인증번호를 만들어 그 이메일로 보내고, 사용자가 받은 번호를 입력하면 주소의 주인임이 확인된다.

## 핵심 개념

**인증번호** — 여섯 자리 숫자로 만들어진다. 발급할 때마다 새로 만들어지며 사람이 지정할 수 없다.

**유효시간** — 인증번호는 발급된 시점부터 5분 동안만 쓸 수 있다. 사용자에게 보내는 메일 문구에도 같은 5분이 안내되므로, 실제 만료 시간과 안내 문구가 어긋나는 일은 없다.

**인증 용도** — 회원가입용과 비밀번호 재설정용 두 가지가 있다. 번호를 만드는 방식과 유효시간, 확인 규칙은 두 용도가 완전히 같고, 다른 것은 사용자에게 보내는 메일의 제목과 본문 문구뿐이다. 회원가입 안내와 비밀번호 재설정 안내가 섞이면 사용자가 혼란스러워지므로 문구를 나눠 둔 것이다.

**인증 상태** — 확인 대기, 인증 완료, 만료 세 가지다.

## 주요 업무 흐름

사용자가 회원가입 화면에서 이메일을 입력하고 인증번호 발송을 요청한다. 그러면 서비스는 먼저 그 이메일로 이미 가입한 회원이 있는지 확인한다. 이미 가입된 주소라면 인증번호를 보내지 않고 그 자리에서 거절한다.

가입 가능한 주소라면 다음 순서로 처리된다. 우선 같은 이메일로 앞서 발급했던, 아직 확인되지 않은 인증번호를 모두 만료시킨다. 사용자가 발송 버튼을 여러 번 눌렀을 때 옛 번호가 계속 살아 있으면 안 되기 때문이며, 이 처리 덕분에 언제나 가장 최근에 받은 번호만 유효하다. 그다음 새 인증번호를 만들어 저장하고, 곧바로 그 번호를 담은 메일을 보낸다.

**여기서 이 도메인의 가장 중요한 규칙이 나온다. 인증번호를 만들어 두는 일과 실제로 메일을 보내는 일은 항상 함께 처리된다.** 과거에는 이 두 가지가 분리되어 있어서, 인증번호는 시스템에 저장됐지만 메일은 실제로 나가지 않는 일이 있었다. 사용자는 "발송되었습니다"라는 응답을 받고 메일함을 기다리는데 아무것도 오지 않는 상황이다. 그래서 지금은 둘을 붙여서 처리한다. 메일 발송이 실패하면 인증번호도 남지 않고 사용자에게 실패했다는 응답이 간다. 발송에 실패했을 때 "번호는 있는데 메일은 오지 않은" 어중간한 상태로 남기는 대신 아예 실패로 처리하는 편이 사용자에게 정직하기 때문이다. 운영·QA 관점에서는 "발송 성공 응답을 받았다면 메일은 반드시 나갔다"고 믿을 수 있다는 뜻이 된다.

사용자가 메일에서 번호를 확인해 입력하면 확인 절차가 진행된다. 서비스는 그 이메일로 발급된 확인 대기 상태의 인증번호를 찾아, 만료되지 않았는지 보고 번호가 맞는지 대조한다. 둘 다 통과하면 인증 완료로 바뀌고 확인 시각이 기록된다.

인증이 완료되면 사용자는 짧은 시간 동안 유효한 인증 증표를 받는다. 회원가입 화면은 이 증표를 함께 보내 "이 이메일은 방금 인증받았다"는 사실을 증명한다. 즉 인증 화면과 가입 화면이 나뉘어 있어도 인증 없이 가입이 통과되지 않는다.

비밀번호 재설정도 같은 구조로 동작한다. 다만 회원가입 쪽과 달리, 인증이 완료됐다는 사실을 시스템 내부에 알리는 처리는 회원가입 흐름에만 걸려 있다. 비밀번호 재설정을 회원가입으로 잘못 세는 일을 막기 위한 구분이며, 앞으로 가입 완료를 계기로 쿠폰을 주거나 가입 통계를 낼 때 숫자가 어긋나지 않게 하는 장치다.

## 상태와 전이 규칙

| 상태 | 의미 |
| --- | --- |
| 확인 대기 | 인증번호가 발급되어 메일로 나갔고 아직 확인되지 않은 상태다. 발급 직후의 상태다. |
| 인증 완료 | 사용자가 올바른 번호를 유효시간 안에 입력해 확인된 상태다. |
| 만료 | 더 이상 쓸 수 없는 상태다. |

만료가 되는 경우는 두 가지다. 하나는 유효시간 5분이 지난 뒤 번호를 입력했을 때이고, 다른 하나는 같은 이메일로 새 인증번호를 발급받아 이전 번호가 밀려났을 때다.

## 비즈니스 규칙

| 규칙 | 위반하면 어떻게 되는가 |
| --- | --- |
| 이미 가입된 이메일로는 회원가입 인증번호를 받을 수 없다 | 이미 등록된 이메일이라는 안내가 나오고 메일도 발송되지 않는다. |
| 인증번호는 발급 후 5분 안에 입력해야 한다 | 5분이 지나 입력하면 만료되었다는 안내가 나오고, 그 번호는 만료 처리된다. 다시 발송을 요청해야 한다. |
| 인증번호는 정확히 일치해야 한다 | 틀리면 번호가 일치하지 않는다는 안내가 나온다. 이 경우 번호는 만료되지 않으므로 유효시간 안에 다시 입력할 수 있다. |
| 같은 이메일로 새 번호를 받으면 이전 번호는 못 쓴다 | 옛 메일에 적힌 번호를 입력하면 일치하지 않는다는 안내가 나온다. 가장 마지막에 받은 메일의 번호를 써야 한다. |
| 발급된 번호가 없으면 확인할 수 없다 | 발송 요청을 한 적이 없거나 이미 처리된 상태에서 확인을 시도하면 인증번호를 찾을 수 없다는 안내가 나온다. |
| 같은 이메일로 하루에 다섯 번까지만 발송을 요청할 수 있다 | 여섯 번째 요청은 막힌다. 24시간이 지나면 다시 요청할 수 있다. 남의 메일함에 인증 메일을 무한정 보내는 것과, 번호를 무작위로 찍어 맞히려는 시도를 함께 막는 목적이다. |
| 메일 발송이 실패하면 인증번호도 남지 않는다 | 사용자는 실패 응답을 받는다. 다시 요청하면 새 번호가 발급되고 발송이 다시 시도된다. |

인증 완료 후 받는 증표는 10분 동안만 유효하다. 인증만 하고 가입 화면을 오래 방치하면 다시 인증해야 한다.

## 다른 도메인과의 관계

**회원** — 가장 밀접하다. 회원가입 인증은 그 이메일이 아직 가입되지 않았는지 확인하는 것에서 시작하고, 인증이 끝나면 가입 절차로 이어진다. 비밀번호 재설정도 회원 계정을 대상으로 한다.

**휴대폰번호 인증** — 구조가 똑같은 자매 도메인이다. 회원가입에는 이메일 인증이, 개인정보에서 휴대폰번호를 바꿀 때는 휴대폰번호 인증이 쓰인다.

## 사용자별 접점

**일반 회원(웹)** — 회원가입 화면에서 이메일 인증을 거치고, 비밀번호를 잊었을 때 재설정 과정에서 다시 이메일 인증을 거친다. 사용자 입장에서 보이는 것은 "인증번호 발송" 버튼과 번호 입력란, 그리고 메일함에 도착하는 인증 메일이다.

**관리자** — 관리자 계정은 이 인증을 쓰지 않는다. 인증 발급 이력을 조회하는 관리 화면도 없다.

**점주** — 지금은 점주 화면에서 이메일 인증을 쓰지 않는다.

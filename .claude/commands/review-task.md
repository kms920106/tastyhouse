현재 커밋 대기 중인 변경(git status / git diff)을 리뷰해줘. 리뷰는 반드시 Skill 도구로 `oh-my-claudecode:review` 스킬을 호출해서 진행해. 아래 "대조 기준"·"재지적 금지"·"제약"·"보고 형식"·"추가 지시"는 모두 그 스킬에 넘기는 지시로 함께 전달해. 특히 "추가 지시"에 들어온 인자(스펙 파일 경로 등)가 빠지지 않게 스킬 호출 인자에 그대로 포함해.

## 대조 기준
- 인자에 파일이 있으면 그것을 기준 스펙으로 쓰고, 없으면 docs/tasks/ 에서 이번 변경과 맞는 backend.md·frontend.md를 찾아 대조해.
- docs/tasks/review-decisions.md가 있으면 먼저 읽어. 위치는 항상 이 한 곳이며, 스펙이 하위 폴더에 있어도 같아. 파일이 없으면 기록 없이 진행해.
- 이번 리뷰의 기록은 덩어리 칸이 **기준 스펙 경로에서 `docs/tasks/` 바로 아래 첫 폴더 이름**(스펙이 루트면 `-`)과 같은 행이야. 하위 폴더 깊이는 무시해. 예: `docs/tasks/pg-confirm-recovery/07-review-followup-3/backend.md` → `pg-confirm-recovery`.
- 기준 스펙을 못 정했으면 변경 파일(git diff)과 가장 많이 맞는 스펙을, 그래도 같으면 가장 최근 수정된 폴더를 골라. 위치·덩어리를 사용자에게 되묻지 말고(AskUserQuestion 금지), 고른 근거를 보고에 한 줄로 적어.
- 표의 열 순서는 파일 헤더를 따라.

## 재지적 금지
- review-decisions.md에 "수정함" 또는 "수정 안 함"으로 기록된 항목은 다시 지적하지 마.
- 단, 기록된 대상 코드가 그 뒤 다시 바뀌었거나 "재지적 허용 조건"에 해당하면 근거를 밝히고 다시 지적해.
- 기록과 비슷해 보이지만 다른 코드·다른 원인의 문제는 새 지적으로 다뤄.

## 제약
- 소스 수정·커밋·빌드·서버 기동은 하지 마. 리뷰만 해.
- 모든 보고는 한국어로 작성해.

## 보고 형식
심각도 순 지적 목록, 이번에 재지적하지 않고 건너뛴 기록 항목 수, 검증하지 못한 것, 추천 커밋 메시지.

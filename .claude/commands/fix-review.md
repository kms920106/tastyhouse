아래 코드 리뷰 지적을 처리해줘. 대상은 현재 커밋 대기 중인 변경(git status / git diff)이다.
기준 스펙은 인자에 파일이 있으면 그것을 우선하고, 없으면 docs/tasks/ 에서 이번 변경과 맞는 backend.md·frontend.md를 찾아 대조해.

## 처리 기준
- 지적마다 코드를 직접 읽어 실제 결함·개선 필요 여부를 먼저 판정해. 리뷰를 맹신하지 마.
- 실제로 개선이 필요한 것만 수정해. 수정하지 않은 항목은 이유를 보고해.
- 스펙이 후속 범위로 미뤘거나 스펙 의도와 일치하는 지적은 수정하지 마.
- "참고" 등급은 코드 변경 없이, 필요하면 문서(AGENTS.md / docs/domain)에만 반영해.
- 리뷰에 없는 리팩터링·범위 확장은 하지 마.

## 제약
- 커밋·롤백 금지. 완료 후 추천 커밋 메시지만 제시해.
- backend java에 주석 추가 금지. 설명은 모듈 AGENTS.md나 docs/domain에 적어.
- 규칙·동작이 바뀌면 관련 AGENTS.md / docs/domain(결정 경위는 그 문서의 `## 결정 경위` 절)도 갱신해. docs/adr 같은 결정 전용 파일은 만들지 마.
- 포트·시그니처를 바꾸면 테스트 스텁과 호출부를 grep으로 전수 확인해.
- backend 검증은 실행 중인 jar를 먼저 내린 뒤 backend 디렉터리에서 ./gradlew build 로 해.
- frontend 빌드와 브라우저 검증은 하지 마. 보고에 "브라우저 검증은 별도 세션 대상"이라고만 적어.
- git stash·reset·checkout 같은 git 변경 명령은 쓰지 마.
- 모든 보고는 한국어로 작성해.

## 판정 기록
기록 형식은 아래 규칙으로 전부 정해져 있어. 위치·덩어리·열 순서·라운드 번호를 사용자에게 되묻지 마(AskUserQuestion 금지). 애매해 보여도 아래 규칙대로 정하고, 어떻게 정했는지만 보고에 한 줄로 적어.

- **파일 위치**: 항상 docs/tasks/review-decisions.md 하나. 스펙이 몇 단계 하위 폴더에 있어도 같다.
- **덩어리 칸**: 기준 스펙 경로에서 `docs/tasks/` 바로 아래 **첫 폴더 이름만** 쓴다. 깊이는 무시한다.
  - `docs/tasks/pg-confirm-recovery/07-review-followup-3/backend.md` → `pg-confirm-recovery`
  - `docs/tasks/m1-pg-confirm-race/backend.md` → `m1-pg-confirm-race`
  - `docs/tasks/backend.md`(루트) → `-`
  - 이유: 후속 폴더(05·06·07-review-followup…)가 계속 생겨도 같은 작업의 연장이라 한 덩어리로 묶어야 이전 판정이 이어진다.
- **기준 스펙을 못 정했을 때**: 인자에 스펙 파일이 없고 변경과 맞는 스펙이 여러 개면, 이번 변경 파일(git diff)이 가장 많이 언급된 스펙을 고른다. 그래도 같으면 `ls -t`로 가장 최근에 수정된 폴더를 고른다. 어느 쪽이든 되묻지 말고 고른 근거를 보고한다.
- **라운드 칸**: 같은 덩어리 행 중 최댓값 + 1. 그 덩어리에 행이 없으면 1. 후속 폴더가 생겨도 1로 되돌리지 않는다. 한 번의 처리에서 나온 모든 행은 같은 라운드 번호를 쓴다.
- **열 순서**: 파일이 이미 있으면 그 헤더의 열 순서를 그대로 따른다. 기존 행의 값·순서를 고치거나 재정렬하지 않는다. 새로 만들 때만 아래 형식을 쓴다.
- 이미 기록된 행은 지우거나 고치지 말고 새 행만 추가한다.
- 수정함·수정 안 함 모두 기록하고, 수정 안 함에는 근거와 재지적 허용 조건을 적는다.
- 대상 칸에는 리포 루트 기준 파일 경로와 코드 요소명을 적는다. 줄 번호는 쓰지 않는다.

파일을 새로 만들 때 형식:

```markdown
# 리뷰 판정 기록

| 라운드 | 덩어리 | 지적 요약 | 대상(파일 경로 · 코드 요소명) | 판정 | 근거 | 재지적 허용 조건 |
|---|---|---|---|---|---|---|
```

## 보고 형식
지적별 "수정함 / 수정 안 함(이유)" 표, 변경 파일 목록, 빌드·테스트 결과, review-decisions.md 경로, 추천 커밋 메시지(최근 git log 컨벤션 `{type}({scope}): {한글 요약}`).
